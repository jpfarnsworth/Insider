# Read-only MCP server at /api/mcp

Added an MCP server modelled on the Life OS one so Claude can query the research: signals, performance, gates and pipeline health. It is read-only, and Phase 2 trading tools must get a separate read-write token.

## What changed
- `app/api/mcp/route.ts`: stateless HTTP transport, open CORS for claude.ai, bearer token `MCP_READ_TOKEN` (at least 32 chars, constant-time compare, closed if unset). `proxy.ts` lets `/api/mcp` through, so the route's own check is the access control (the one exception to "requireUser everywhere"). Every request is logged to `mcp_request_logs` (no arguments).
- Tools (`lib/mcp/tools.ts`): `list_signals`, `get_signal`, `get_performance`, `search`, `pipeline_status`. Thin adapters over the same code the UI uses, so numbers match.
- Filing and agent text is untrusted; the tool descriptions say to treat it as data.

## Verified
- 401 for missing/wrong token; every tool exercised over HTTP; request log rows written. To connect: claude.ai custom connector at the `/api/mcp` URL, or `claude mcp add --transport http ...` (in CLAUDE.md).
